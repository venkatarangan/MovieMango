# Architecture

A static PWA with no backend. The browser talks directly to TMDB, Wikipedia, WordPress.com (Mangoidiots), Google (Drive, Gemini) and Hugging Face (Qwen weights).

| Folder | What's there |
|---|---|
| `src/api` | TMDB, Wikipedia and Mangoidiots clients; rate-limited fetch, session + IndexedDB cache, recent-titles store (`recent.ts`) |
| `src/ai` | Engines (Gemini Nano, Qwen/WebLLM, Gemini REST), automatic engine choice, prompts |
| `src/reco` | Taste profile (`profile.ts`), scoring, the Tonight pipeline, Home shelves (`home.ts`: `worldShelf`, `languageOfWeek`, `languageShelf`) |
| `src/db` | Dexie tables (items, lists, kv settings, cache, titles, streaming); `items.ts` has `inView` (views `watchlist`/`watched`/`loved`/`notforme` or a custom list id), `restoreItem` and `setUserNotes`; `streaming.ts` is the one streaming checker and store |
| `src/sync` | Google sign-in, the Drive app-folder file, sync scheduling, merging |
| `src/lib` | India OTT catalogue, languages (`WORLD_LANGUAGES`, `otherLanguages`, `languageCode`), ratings (`MY_RATINGS`, `ratingText`), list view sort/filter (`listView.ts`), browse filter parsing (`browse.ts`), export/share, Markdown parse/export and import matching, custom titles, episode logic, analytics |
| `src/components` | UI pieces. `TitleActions.tsx`: `ItemsProvider` (one live query for all saved items), `useTitleActions` (every change gets a toast with Undo), `MyRatingButtons`, `QuickActions`. `ListView.tsx`: chips, sort, filters, Streaming dropdown, ⟳ refresh, find. `Streaming.tsx`: `StreamingProvider` (one live query for all streaming rows), `useCheckWhenVisible`, `StreamingBadge`. `MyNotes.tsx`: your link and notes |
| `src/pages` | Routes: `/` Home, `/tonight`, `/search`, `/title/:type/:id`, `/browse/:type` (genre pages), `/person/:id`, `/library`, `/list/:id`, `/import`, `/reviews`, `/settings`, `/about`, `/privacy`, `/welcome` |

**Key decisions**
- **AI never invents titles.** TMDB supplies real candidates (filtered by the user's services, languages, runtime and certificate) and a scoring formula ranks them; the model only re-ranks and explains. If AI fails, the scored list is shown.
- **Engine order:** Nano → Qwen (if downloaded) → Gemini (if a key is saved). Downloads only start when the user taps; Basic mode only when the user picks it. The UI calls this "Local AI by default"; a cloud model is used only with the user's own Gemini key.
- **Status and ratings:** `BUILTIN_LISTS` = `watchlist`, `watched` (TV also tracks episodes). One optional `rating` per item, `MyRating` = `dislike | like | love` (👎 Not for me, 👍 Liked it, ❤️ Loved it; labels in `src/lib/ratings.ts`). 👍/❤️ add `watched` and drop `watchlist`; 👎 drops `watchlist` and keeps the title out of Tonight and Home rows; adding a 👎 title to the watchlist clears the 👎. `MangoRating` is only for Mangoidiots reviews. Taste weights (`profile.ts`): ❤️ 3, 👍 2, watched 1, watchlist +1, 👎 −2. Up to 50 custom lists.
- **Title page:** Watchlist / Watched / Lists buttons, then 👎 👍 ❤️ (`MyRatingButtons`). Genre chips link to `/browse/:type?genre=…`; director/creator and cast names link to `/person/:id`.
- **Poster actions:** `PosterCard` shows `QuickActions` (＋ menu: Watchlist, Watched, 👍, ❤️; and 👎) unless it's a picker (`onClick`). Saved state comes from `ItemsProvider`; `useTitleActions` gives every change a toast with Undo (`restoreItem`). `ScrollRow` adds ‹ › on `(hover: hover) and (pointer: fine)`.
- **Library views:** tabs Watchlist, Watched, ❤️ Loved, 👎 Not for me (by rating, `inView`), My lists. `ListView` (logic in `src/lib/listView.ts`) adds Films/Shows chips with counts, sort (Recently added, Recently watched, Title A–Z, Newest release, Oldest release, Your rating, TMDB rating, Shortest first), Streaming (`service`: `mine`, a service key or `none`; unchecked and custom titles match nothing), filters (genre, language, your rating, decade) and "Find in this list" (titles, original titles and notes); the view is kept per list in `localStorage` (`mm.view.<list>`).
- **Streaming info (one feature for Home, Library, Browse, title pages):** `src/lib/streaming.ts` (pure) and `src/db/streaming.ts` (store + checker).
  - Dexie `streaming` table (v3), one `StreamingRow` per title key: `services` (`key`, TMDB `logo`, `since` = first seen), `firstCheckedAt`, `checkedAt`, `updatedAt`. Region offers are subscription/free/ads only (`availabilityFrom`).
  - `checkStreaming` is the only per-title TMDB check: library titles keep their first answer until "check again"; titles outside the library are re-checked after 2 days (`STREAMING_FRESH_MS`); `maxAgeMs` forces a re-check (Home's watchlist row, 2 days, which is how "New" arrivals are spotted); `fresh` skips every cache (`getWatchProviders(…, { fresh })`, `refreshCached`). Custom titles are never checked.
  - One app-wide queue: 3 at a time, 200 ms between starts, 30 s pause after 429/5xx, one request per title in flight, aborted jobs (posters scrolled away) dropped before they start. `checkMany` reports progress and counts changes/failures.
  - `recordStreaming(…, { checked: false })` takes free data from a title page's details, writing only when services changed or nothing was saved, so viewing a title doesn't re-sync it.
  - Posters: `PosterCard streaming="check"` (Library, Browse) checks after the poster has been on screen 500 ms (`useCheckWhenVisible`); default `"show"` uses saved rows only (Home rows, recommendations). Logos sit bottom-left (the ＋/👎 buttons are top-right): your services first, up to 2 then "+n", others only when none of yours; "New" = one of your services arrived after the first check, within 7 days (`isNewRow`).
  - Library: the Streaming menu checks every unchecked title when opened (or when a remembered filter is set); ⟳ re-checks titles that have saved info (`fresh`) and toasts how many changed. Browse: the dropdown sends `with_watch_providers` to discover (no per-title checks); with one service, `streamHint` gives every poster its logo for free.
  - Sync: rows for titles in the library (`isSaved`) go in the Drive payload (`streaming`, optional, newest-wins per key, dropped when a title leaves the library). `onLibraryStreamingChanged` schedules a batched sync. Other rows stay local; `pruneStreaming` drops them after 30 days. `migrateStreamSeen` moved Home's old kv `streamSeen` into the table.
- **Your link and notes:** `UserItem.watchLink` (http/https, ≤ 2000 chars, `cleanWatchLink`) and `notes` (≤ 1024 UTF-8 bytes, `clampBytes`), on any saved title; set via `setUserNotes` (adds an unsaved title to the Watchlist). Title page and custom title page: `MyNotes` card (saves on blur) and a "Your link" button (`MyLinkButton`, `rel=noopener noreferrer`, shows the host). Posters show a notes mark. Left out of text shares; included in Markdown.
- **Sync:** one JSON file in Drive's `appDataFolder`, newest-wins per record.
  - Batching: the first unsynced change starts a 2-minute timer (later changes don't extend it); everything changed in that window goes up in one sync. Also syncs on app open, on tab hide/leave (flushes pending changes), on return after 2+ minutes hidden (to pick up other devices' changes), and on "Sync now".
  - One sync = at most 3 Drive calls: file metadata; download only if the Drive file changed since our last sync; upload only if something changed. Only one sync runs at a time.
  - 429, 403 rate-limit reasons and 5xx are retried with exponential backoff and jitter, up to 5 tries.
  - Per-device options: `driveAutoSync` (off = only "Sync now"; pending changes turn the cloud icon orange) and `driveSyncKeys` (off = keys stripped from both sides before merging, so they leave the Drive file). Tokens last about an hour, then the header shows "Reconnect Drive".
- **Home** (`/`, `src/pages/Home.tsx`, `src/reco/home.ts`): search with suggestions; "Feeling lucky?" = `planTonight` with no engine, time-of-day defaults and a 12-title shortlist, cached for the session; Continue watching (`useShowsInProgress`); watchlist titles on the user's services (`streamingNow`: up to 24, through the shared streaming store, "New" for 7 days); Movies for you and Shows for you (random from one of 6 discover pages per type); 🌏 World picks for you; "🗣️ This week: <language>"; Latest on your watchlist; Recently watched.
- **Other languages:** `WORLD_LANGUAGES` minus the user's (`src/lib/languages.ts`). World picks = acclaimed titles in other languages, on the user's services, in their top genres. Language of the week changes every Monday and moves to the next language if fewer than 4 titles stream. Tonight's "Any language (subtitles OK)" (`anyLanguage`) drops the language filter and adds a `world` discover source. Tonight card buttons: Watchlist, Watched, Liked it, Loved it, Not for me.
- **Tonight list size:** `PICKS_SHOWN` (10) are shown and AI-explained; up to `PICKS_TOTAL` (20) are kept, the rest in reserve with `basicWhy` and shown as the user sorts picks (`Tonight.tsx` slices the unhidden picks). The AI sees only `AI_POOL` (20) candidates (about 60 tokens each) and writes 10 reasons, to fit small context windows (Gemini Nano about 6k, Qwen about 4k) and `max_tokens: 900`. Home's lucky picks pass `total: 6`.
- **Tonight state (`src/reco/tonightState.ts`):** one store shared by Tonight and Home's Feeling lucky: the choices (`input`) and the last run (`run`: result, `hidden` keys, `at`, `by` user/auto, `sig`). Memory copy (instant on remount) plus the Dexie `kv` row `tonight`, never synced. Valid for 6 h (`STATE_TTL_MS`) and only for the same `settingsSig` (region, services, languages, showAllRatings). `ensureTonightRun` builds a no-AI run when none is valid (Home and Tonight both call it; one in flight, no retry loop after a failure). `hiddenKeys` = acted on in Tonight, or watched/👎/newly saved in the library (a pick that was on the watchlist at run time, `Pick.onWatchlist`, stays until acted on). Services hold a function, so `packState`/`unpackState` store them by key. Home slots (`useSlots`) keep the other two positions steady.
- **Tonight TMDB cost:** `planTonight` enriches in waves (first `ENRICH_COUNT` 24, then `ENRICH_MORE` 12 while fewer than `total` titles pass, up to `MAX_ENRICH` 48). Reviews: top `MANGO_CHECK` 16 only. `tests/tmdbCalls.test.ts` prints counts; `e2e/smoke.spec.ts` asserts zero TMDB calls after a reload on Tonight.
- **Browse** (`src/pages/Browse.tsx`): newest released 100 (5 TMDB discover pages), Next/Previous 100. URL params `genre`, `sort` (new/popular/top), `year` (2019 or 1990s), `lang`, `theme` (resolved to up to 3 TMDB keyword ids via `/search/keyword`, OR'd), `on` (Streaming: `mine` or a service key; old `mine=1` links still work), `mylangs`, `p`. A vote floor skips placeholders. The filter box text is split into theme, year/decade and language by `parseFilterText` (`src/lib/browse.ts`).
- **People** (`src/pages/Person.tsx`): `/person/{id}?append_to_response=combined_credits` (7d cache). Acting and Directing tabs, newest first, Films/Shows chips. Acting leaves out talk/news/reality shows and "Self" roles; Directing is Director or Creator jobs.
- **Search links:** `main.tsx` rewrites `/?q=…` to `#/search?q=…`. `public/opensearch.xml` uses the hash form so the term stays in the browser.
- **TMDB caching** (`src/api/http.ts`, `src/api/recent.ts`, `src/api/tmdb.ts`): call TMDB as little as possible.
  - Read path: session `Map` (500 entries) → Dexie `cache` → network. Concurrent identical requests share one fetch. Params are normalised (sorted keys, sorted `|`/`,` id lists, empty dropped) so equivalent requests share a row.
  - Expired rows are returned instead of an error when offline, on 429/5xx or network failure (then no retry for 2 min). `pruneCache` keeps expired rows 30 days for this, cap 4000.
  - TTL / stale-while-revalidate window: search 1h / none; trending 6h / 1d; discover 12h / 3d; recommendations 7d / 30d; provider catalogue 7d / 60d; season 1d (30d once its last episode is 60+ days old).
  - Details live in the Dexie `titles` table, not `cache`: last 250 titles (`RECENT_MAX`), LRU by `accessedAt`. Core data fresh 30d (7d for running TV, unreleased or <120-day-old movies). Watch providers more than 2d old are refreshed in the background via `/{type}/{id}/watch/providers`, old copy served meanwhile. Page 1 of `getRecommendations` comes from stored details. `peekDetails` (no network) and `getWatchProviders` read the same store.
  - `db.cache.clear()` (Settings → Clear cache) also clears memory and `titles` (Dexie middleware in `src/db/index.ts`).
  - Dev builds count requests in `window.__tmdbCalls` (`{ total, byPath }`) and log each with `console.debug`. `tests/tmdbCalls.test.ts` prints counts for a Tonight run.
- **Custom titles** (not in TMDB) are normal items with a **negative `tmdbId`** and a `custom` block (`src/lib/types.ts`, `isCustom()`). Never send a negative id to TMDB: Tonight skips them as seeds and candidates; `/title/:type/-id` renders `CustomTitleView`. Delete = empty lists (a tombstone, so sync doesn't restore it).
- **Markdown import/export** (`src/lib/markdown.ts`): headings name lists, bullets are titles: `- Title (2019) · movie|tv · rating: like · tmdb: 123` (also `imdb:`, `custom`, `url:`, `> description`, and indented `link:` / `notes:` lines for your watch link and notes; `· link:` and `· notes:` inline also work, and a TMDB/IMDb link under `link:` identifies the title). Ratings `dislike | like | love`; 👎 👍 ❤️ also work, and stars/scores map top → love, good → like, bad → dislike, middling → no rating. Headings: `# Watchlist`, `# Watched`, `# Loved` (watched + ❤️), `# Not for me` (👎); any other heading is a custom list. The parser also takes numbered lists, tables and IMDb/Letterboxd CSVs. `/import` matches rows on TMDB (`src/lib/importMatch.ts`), the user reviews, then `applyImport` adds (never removes). Library "Export all" writes Watchlist, Watched, Not for me (👎 titles not watched) and custom lists.
- **Episodes:** TV progress lives on the item (`episodesSeen` per season, cached `nextEpisode`), so it syncs like any item change. Logic in `src/lib/episodes.ts`; Specials (season 0) don't count; unaired episodes are capped by `last_episode_to_air`. Season lists load only when expanded.
- **Privacy:** fonts are self-hosted; GA4 is built in only when `VITE_GA_ID` is set (on by default, opt-out in Settings; ads signals off; only id-stripped page types and feature names, never titles, lists, text, notes or keys; see `src/lib/analytics.ts`); review HTML is sanitised.
